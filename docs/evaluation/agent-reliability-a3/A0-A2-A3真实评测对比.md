# A0–A2–A3 真实 Agent 评测对比

评测日期：2026-07-20

## 结论

A3 达到了系统级工具选择成功率目标：`0.8833 >= 0.80`；确认完整性由 A2 的 `0.6667` 提升到 `0.7778`，但仍低于 `0.85`。失败 Run 从 A0 的 22、A2 的 15 下降到 7；p50/p95、请求数、Token 和成本均明显下降。

A3 有 41 次 Decision 由 Runtime 确定性策略产生，覆盖 32 个 Run。因此 `0.8833` 是“Agent系统工具选择成功率”，不能写成“DeepSeek模型独立工具选择率”。该区分是A3的核心工程结论：可靠性提升主要来自缩小模型责任边界，而非证明模型本身变得更强。

## 可比性

- A0、A2、A3均使用相同20场景×3次固定集。
- A3 Prompt version：`agent-reliability-a3-compact-v1`。
- 格式修复关闭；单请求仍受12,000 UTF-8 bytes和350 completion token限制。
- A0与A2原始报告保持独立文件，没有被覆盖。
- A3使用修复后的fallback统计，并单独统计Runtime确定性Decision。

## 剩余7个失败

```text
agent_case_004: 2
agent_case_014: 2
agent_case_016: 3
```

`004`和`014`的4个失败均在执行Step前发生一次Guard fallback；原始模型文本按隐私策略未保留，因此不能事后伪造具体解析原因。下一阶段应在不保存模型内容的前提下记录脱敏错误分类，例如 `disallowed_action`、`schema_invalid`、`missing_required_field`。

`016`需要特别披露：fixture没有预置可应用draft ID，但要求工具序列包含高风险`apply_confirmed_draft`；runner只为`confirmation`类别自动接受等待确认，而`016`属于`tool_failure`。A3中两次正确选择apply后停在`waiting_confirmation`，受控工具失败没有执行；另一次安全回退。不能通过伪造ID或绕过确认来提高分数。应建立带无效draft和明确确认步骤的v2 fixture，并把旧结果继续单列。

## 是否合并

A3已达到系统工具选择目标，但确认完整性未达到0.85，且`004/014`仍有模型到复盘草稿动作的间歇回退。因此当前保持Draft，不合并到A2或main，也不部署Render。

下一候选应优先合并`create_flashcards/create_quiz`这两个共享底层`create_review_draft`工具的模型选择歧义，或在明确的review-draft objective下由Runtime确定性选择一个规范动作；随后再修订`016`的v2评测契约。
