# 真实 Agent 决策失败分类与可靠性实验基线

更新时间：2026-07-20

## 结论

第七版真实 DeepSeek 固定评测的主要问题不是随机格式波动，而是系统性工具路由与状态理解错误。60 个 Run 中有 22 个失败，分布在 8 个场景；其中 7 个场景连续 3 次全部失败，仅 `agent_case_013` 为 3 次中失败 1 次。因此下一阶段应优先缩小状态对应的动作空间，并把确认和终态控制从自由模型决策中剥离，而不是继续增加工具或扩大产品范围。

本报告只分类已保存失败，不修改 `backend/evaluation/agent_scenarios.json`、原始真实模型报告、通过标准或历史指标。可复现分析命令：

```powershell
python backend/analyze_agent_failures.py
```

## 第一阶段假设

1. 当前 Prompt 同时暴露过多工具，模型偏向高频的 `review_material`、`create_task_draft` 和 `answer_only`。
2. “已存在待确认草稿”“刚刚拒绝”“工具刚失败”“动作已经尝试”等状态虽然进入 Context，但没有转化成明确的可选动作约束。
3. 确认、拒绝、恢复和终态属于运行时控制问题，不应完全依赖模型从自然语言中再次推断。
4. 多步过程中通用任务创建路径过强，覆盖了检索、复盘、反馈记忆和事务恢复的领域意图。

## 实验顺序

所有方案均使用相同 20 × 3 固定集；真实模型复跑前必须重新计算并显式授权请求、Token 和成本上限。

| 方案 | 唯一主要变量 | 预期验证 |
|---|---|---|
| A0 | 第七版原始基线 | 保留 0.6333 / 0.5556 与 22 个失败 Run |
| A1 | 精简工具描述与参数 Schema | 已实现；尚未真实模型复跑 |
| A2 | 按 Run 状态生成 allowed-action mask | 已实现；尚未真实模型复跑 |
| A3 | 确认、拒绝、恢复与终态由确定性策略控制 | 测量确认完整性和终态正确性 |
| A4 | 相关 Context 裁剪 + A2 + A3 | 测量质量、Token、延迟与回退的综合变化 |

一次只引入表中指定的主要变量；如果多个变化同时上线而没有消融，就不能说明提升来自哪里。

## 阶段验收目标

- 工具选择成功率目标 `>= 0.80`。
- 确认完整性目标 `>= 0.85`。
- 恢复成功率保持 `1.0`。
- Guard 注入召回保持 `1.0`，并继续注明其不代表模型自然非法输出率。
- 失败 Run、安全回退、p50/p95、Token、请求数和成本必须与 A0 并列表述。
- 不删除原始失败，不改变场景来迎合实现，不用 Mock 的 `1.0` 替代真实模型结果。
