# 第一版功能开发边界与分工

更新时间：2026-06-30

## 1. 第一版目标

第一版的目标是做出一个可以完整演示、并能继续工程化的最小可用版本。

核心不是把所有想法都做进去，而是先跑通一条完整闭环：

```text
目标 -> 资料 -> AI 整理 -> 计划 -> 打卡 -> 进度
```

完整版本可以扩展为：

```text
注册登录 -> 创建成长目标 -> 添加资料 -> AI 整理资料 -> 生成行动计划 -> 完成今日打卡 -> 查看进度
```

如果开发时间或实现难度需要收敛，优先保住第一条主线。注册登录、PDF 上传、复杂部署默认按阶段后置。

## 2. 阶段拆分

```text
MVP-0：静态 / 本地演示闭环
目标：基于当前 app/ 原型讲清楚产品流程。
允许：localStorage、mock AI、单用户数据。

MVP-1：工程化最小版
目标：加入前后端边界、数据库持久化、最小真实 AI 接口或可替换 AI mock 层。
重点：目标、资料、AI 整理、计划、打卡、进度。

MVP-2：完整化增强
目标：补注册登录、用户隔离、PDF 上传、部署和更完整测试。
```

## 3. 第一版产品边界

第一版定位为“通用成长学习助手 App”的基础版本。

它面向学生、上班族、考证人群、自由职业者和兴趣学习者等多类人群，帮助用户围绕一个成长目标进行资料整理、计划拆解、记忆练习和进度监督。

第一版重点验证：

```text
1. 用户是否愿意创建自己的成长目标。
2. 用户是否愿意添加资料给 AI 整理。
3. AI 整理出的摘要、知识点、计划是否有帮助。
4. 每日任务和打卡是否能推动用户继续使用。
5. 进度展示是否能给用户反馈感。
```

## 4. 第一版必须保住的主线

### 4.1 成长目标管理

必须实现：

```text
创建目标
查看目标列表
查看目标详情
修改目标
删除目标
```

目标字段：

```text
目标名称
所属方向
当前水平
目标完成时间
每天可投入时间
重点难点说明
```

### 4.2 资料管理

必须实现：

```text
添加文本资料
添加网页链接
查看资料列表
查看资料详情
删除资料
```

建议后置：

```text
PDF 上传与解析
复杂网页解析
批量资料导入
```

### 4.3 AI 整理资料

必须实现：

```text
根据资料生成摘要
提炼知识点
给出学习或行动顺序
支持围绕资料提问
```

AI 输出至少包括：

```text
资料摘要
关键知识点
难点解释
建议学习顺序
可执行的小任务
```

### 4.4 行动计划

必须实现：

```text
根据目标和资料生成短期计划
今日任务展示
任务完成打卡
查看计划列表
简单延期调整
```

### 4.5 记忆与练习

必须实现：

```text
根据资料生成闪卡
根据资料生成简单测试题
标记“已掌握”
标记“需复习”
```

### 4.6 进度统计

必须实现：

```text
目标完成率
今日任务完成情况
已完成任务数
资料数量
闪卡数量
简单进度条
```

```text

用户数据隔离
```


## 6. 两人模块分工

当前采用：

```text
共同定方向 + 功能闭环主责 + 交叉评审
```

日常开发主规则：

```text
以后日常模块分工优先按 docs/daily/2026-06-30工作安排.md 推进。
重大技术边界、数据对象、API 命名、MVP 阶段取舍和最终验收仍然共同评审。
```

共同负责：

```text
MVP 边界
功能优先级
核心流程
接口字段确认
导师待确认问题
最终演示和验收
```

陈主责：

```text
目标管理 -> 行动计划 -> 今日任务 -> 打卡 -> 进度统计
页面流程、用户体验、PRD 表达、验收标准、演示讲解
```

赵主责：

```text
资料管理 -> AI 整理 -> 闪卡 / 测试题 -> 成长问答
技术栈、工程结构、数据模型、API、AI 接口、Git 和部署方案
```

## 7. 模块分配表

| 模块 | 主责 | 协作方式 |
|---|---|---|
| MVP 边界 | 共同 | 一起取舍，不单独决定 |
| 目标管理 | 陈 | 赵确认数据结构和接口 |
| 行动计划 | 陈 | 赵确认生成逻辑和实现成本 |
| 今日任务、打卡与进度 | 陈 | 赵确认持久化和统计逻辑 |
| 页面流程 | 陈 | 赵确认技术可行性 |
| 资料管理 | 赵 | 陈确认使用场景和体验 |
| AI 整理 | 赵 | 陈确认输出是否有用 |
| 闪卡 / 测试题 / 问答 | 赵 | 陈确认学习体验 |
| 数据模型和 API | 赵 | 陈确认字段是否满足页面 |
| Git、部署、技术方案 | 赵 | 陈参与基础流程和验收 |
| Demo 演示 | 共同 | 陈主讲体验，赵补充技术实现 |

## 8. 第一版开发优先级

建议按以下顺序推进：

```text
1. 第一版技术实现方案
2. MVP 边界和验收标准确认
3. 数据对象和 API 字段确认
4. 项目基础结构
5. 目标管理
6. 资料管理
7. AI 资料整理
8. 行动计划生成
9. 今日任务与打卡
10. 闪卡和测试题
11. 进度统计
12. 整体联调和演示版本
```

## 9. 第一版总体验收标准

第一版最终验收时，必须能够完成以下流程：

```text
1. 用户创建一个成长目标。
2. 用户添加一份资料。
3. 系统通过 AI 或 mock AI 整理资料重点。
4. 系统根据目标和资料生成行动计划。
5. 用户在今日页面完成任务打卡。
6. 用户查看目标进度。
7. 用户可以看到由资料生成的闪卡或测试题。
```

如果加入注册登录，则额外验收：

```text
1. 用户可以注册并登录。
2. 登录后只能看到自己的数据。
3. 刷新页面后登录状态和数据不应异常丢失。
```

```text
目标 -> 资料 -> AI 整理 -> 计划 -> 打卡 -> 进度
```
