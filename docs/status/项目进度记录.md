## 2. 第一版产品闭环

第一版优先保住这条主线：

```text
目标 -> 资料 -> AI 整理 -> 计划 -> 打卡 -> 进度
```

完整形态可以扩展为：

```text
注册登录 -> 创建成长目标 -> 添加资料 -> AI 整理资料 -> 生成行动计划 -> 完成今日打卡 -> 查看进度
```

阶段口径：

```text
MVP-0：静态 / 本地演示闭环，允许 localStorage 和 mock AI，目标是讲清楚产品流程。
MVP-1：工程化最小版，加入前后端边界、数据库持久化、最小真实 AI 接口或可替换 mock 层。
MVP-2：补注册登录、用户隔离、PDF 上传、部署和更完整测试。
```


## 6. 分支协作规则

当前仓库使用 4 个分支协作：

```text
main                         稳定版本 / 最终演示版本
dev                          两人功能合并后的测试分支
feature/goal-plan-checkin    陈负责模块分支
feature/material-ai-memory   赵负责模块分支
```

开发流向：

```text
feature/goal-plan-checkin  \
                            -> dev -> main
feature/material-ai-memory /
```

使用规则：

```text
1. 陈的模块先提交到 feature/goal-plan-checkin。
2. 赵的模块先提交到 feature/material-ai-memory。
3. 两个功能分支完成自测后合并到 dev。
4. dev 跑完整主线和联调测试。
5. 测试稳定后再合并到 main。
6. main 只保留稳定可演示版本。
```
