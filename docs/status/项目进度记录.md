
## 2. 第一版产品闭环

第一版优先保住这条主线：

```text
目标 -> 资料 -> AI 整理 -> 计划 -> 打卡 -> 进度
```

当前 MVP 第一版验收主线：

```text
创建目标
-> 新增资料并绑定目标
-> 生成资料摘要
-> 生成闪卡/测试题
-> 生成行动计划
-> 今日任务打卡
-> 查看进度
-> 重启后端后数据仍存在
```

阶段口径：

```text
MVP-0：静态 / 本地演示闭环，允许 localStorage 和 mock AI，目标是讲清楚产品流程。
MVP-1A：FastAPI + SQLite + 基础 API + 自动化测试，保证核心数据可持久化。
MVP-1B：前端全量接后端 API，README / 接口文档 / CI 补齐，形成稳定演示版本。
MVP-2：注册登录、用户隔离、真实 AI、PDF 上传、部署、RAG 和更完整测试。
```

当前判断：

```text
MVP-1A 基本完成。
MVP-1B 准备开始，重点是前端接 API 和工程质量整理。
```

## 7. 分支协作规则

当前推荐分支流向：

```text
feature/xxx -> dev -> main
```

使用规则：

```text
1. 开发新功能前先同步 dev。
2. 从最新 dev 新建功能分支。
3. 功能完成后先自测。
4. 提交 PR 合并到 dev。
5. dev 跑完整主线和联调测试。
6. dev 稳定后再考虑合并到 main。
7. main 只保留稳定可演示版本。
```

当前分支状态：

```text
dev：当前集成分支，已包含目标模块 SQLite、资料模块 SQLite、测试加固和最新文档。
main：稳定版本分支，是否合入 dev 需要等 MVP 第一版完整验收后决定。
feature/goal-module-sqlite：陈模块已合入 dev。
feature/material-sqlite-hardening：资料模块测试加固已合入 dev。
feature/zhao-sql-persistence：赵模块 SQLite 持久化已进入 dev 历史。
```

建议：

```text
后续不要长期复用旧 feature 分支。
每个新任务从最新 dev 新建小分支，完成后 PR 合回 dev。
```
