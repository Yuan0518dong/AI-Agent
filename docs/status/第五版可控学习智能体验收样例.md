# 第五版可控学习智能体验收样例

更新时间：2026-07-09

## 验收目标

验证第五版 AI-Agent 已经从“可控学习智能体闭环 MVP”升级为更完整的垂直学习 Agent：

```text
1. Agent 能读取学习状态并生成结构化决策。
2. Agent 能把 actionType 映射为受控工具，并标注风险等级。
3. Agent 能记录一次运行轨迹，保留 context / decision 快照。
4. Agent 能根据用户反馈调整下一轮建议。
5. Agent 能尝试 LLM JSON 结构化决策，并在失败时回退 rule-based。
6. Agent 能评审模型输出，非法动作回退，高风险动作强制确认。
```

第五版验收重点不是回答是否“像人”，而是闭环是否可追踪、可确认、可回退、可验证。

## 核心链路

```text
AgentContext
-> AgentDecision
-> Tool Registry
-> AgentActionLog
-> AgentRun
-> 用户确认式执行
-> 下一轮上下文回读
-> LLM JSON Decision / rule-based fallback
-> Decision Guard 输出评审
```

## 场景一：任务逾期 / 缺少任务时生成任务草稿建议

触发方式：

```text
创建目标，但不生成任务；或让目标下出现逾期未完成任务。
调用 POST /api/agent/decide?goalId=...
```

预期：

```text
problems 包含 missing_tasks 或 overdue_tasks
nextAction 为 create_followup_tasks 或 reschedule_tasks
proposedActions[0].toolName = create_task_draft
proposedActions[0].riskLevel = high
proposedActions[0].draftOnly = true
proposedActions[0].requiresConfirmation = true
```

说明：

```text
任务计划会影响用户真实学习路径，所以必须进入草稿态或确认流程，不能让 Agent 直接改 tasks 表。
```

## 场景三：资料不足时建议补充资料

触发方式：

```text
对当前资料提出资料外问题。
Agent ask 记录 material_insufficiency。
再调用 POST /api/agent/decide?goalId=...
```

预期：

```text
Agent ask 返回 isFromMaterial=false
nextAction=ask_for_more_material
AgentDecision problems 包含 material_insufficiency
ask_for_more_material 映射到 toolName=suggest_material_gap
draftOnly = true
applyTarget = materials
```

说明：

```text
资料不足不是失败，而是可控 Agent 的边界表达：模型不能把资料外常识伪装成资料依据。
```

## 场景四：反馈记忆避免重复建议

触发方式：

```text
先让 Agent 生成 create_flashcards 建议。
用户把该建议记录为 rejected。
再次调用 POST /api/agent/decide?goalId=...
```

预期：

```text
feedbackMemory.recentlyRejected 包含 create_flashcards
下一轮 proposedActions 不再立即包含 create_flashcards
reason 中说明 rejected action type was avoided
```

说明：

```text
这证明 Agent 不是每轮只看静态上下文，而是会读取用户反馈历史，避免机械重复。
```

## 场景五：AgentRun 保留运行轨迹

触发方式：

```text
调用 POST /api/agent/runs
再调用 GET /api/agent/runs?goalId=...
再调用 GET /api/agent/runs/{run_id}
```

预期：

```text
列表接口返回 contextSummary / decisionSummary / feedbackSummary
详情接口返回 contextSnapshot / decisionSnapshot
PATCH /api/agent/runs/{run_id} 后反馈摘要会重新汇总 ActionLog
```

说明：

```text
ActionLog 记录单个建议反馈；AgentRun 记录一次智能体运行。
这个拆分让项目可以讲清 Agent 生命周期，而不是只保存按钮点击记录。
```


## 场景六：LLM JSON Decision hybrid 回退

触发方式：


预期：


说明：

```text
模型 JSON 失败、字段缺失或非法 actionType 时，系统回退 rule-based，并继续通过 Tool Registry 约束风险。
```

## 场景七：Decision Guard 评审模型输出

触发方式：

```text
让 mock LLM 返回高风险动作 reschedule_tasks，但 requiresConfirmation=false。
调用 POST /api/agent/decide?goalId=...&decisionMode=hybrid
```

预期：

```text
mode = hybrid
decisionGuard.status = sanitized
decisionGuard.interventions[0].type = force_confirmation
proposedActions[0].toolName = create_task_draft
proposedActions[0].riskLevel = high
proposedActions[0].draftOnly = true
proposedActions[0].requiresConfirmation = true
```

说明：

```text
Decision Guard 不替代 Tool Registry。它先判断模型输出是否能进入系统；
Tool Registry 再提供动作对应的工具、风险等级和确认规则。
如果模型输出未知 actionType，Guard 拒绝并回退 rule-based；
如果模型输出高风险动作但漏了确认要求，Guard 会修正为必须用户确认。
```

自动化证据：

```text

- test_agent_decision_hybrid_falls_back_on_invalid_llm_action
```

## 面试表达

一句话：

```text
我把学习系统升级成了一个可控 Agent：它能读取学习状态，生成结构化决策，把动作映射到带风险等级的工具，记录运行轨迹和用户反馈，并在真实模型结构化决策失败时回退规则决策。
第五版继续加入 Decision Guard，用来评审模型输出：非法动作回退，高风险动作强制确认，避免 LLM 直接把不合规决策送进执行层。
```

技术追问回答：

```text
为什么不让 LLM 直接执行？
因为任务重排、闪卡写入、补资料都会影响用户真实学习路径。我的设计是先让 LLM 或规则层输出 proposedActions，再通过 Tool Registry 标注风险和确认规则，高风险动作只进入草稿态，由用户确认后才写正式表。
```

工程化追问回答：

```text
第五版不是推倒重做，而是兼容式演进：保留旧 actionType 和 rule-based 决策，在外层增加 AgentRun、Tool Registry、Feedback Memory 和 LLM JSON Decision hybrid。这样旧流程继续可用，新能力可以逐步接管解释、校验和展示。
```
