## 文档定位

本文档是第七版开发的唯一实施入口。

目标是在 3-4 周全职等效投入内，将当前工程原型升级为可公开体验、可量化评测、可用于 Agent 应用后端岗位简历的完整项目。若按课余时间推进，应按 5-7 个日历周安排，不通过压缩测试或评测范围追赶日期。

执行规则：

- 每项需求使用固定编号，完成后更新勾选状态和验证结果。
- 每个批次单独分支、提交和验收，不把四周改动堆在一个提交中。
- README 只展示最终能力，过程记录进入 `docs/status`。
- 简历只使用已经通过测试或评测得到的真实数据。
- 保留原生 JavaScript，不迁移 React/Vue。

## 实施前锁定的技术决策

- 鉴权采用数据库会话，不采用 JWT：服务端生成 32 字节随机不透明令牌，Cookie 名为 `ai_agent_session`，数据库只保存令牌的 SHA-256 哈希。
- Cookie 固定为 `HttpOnly`、`SameSite=Lax`、生产环境 `Secure`；注册用户会话有效期 7 天，Demo 会话与 Demo 用户均为 24 小时。退出登录立即吊销当前会话。
- 同源前端的写请求必须校验 `Origin`；不得重新引入客户端可信用户 ID。现有 PBKDF2 密码在用户成功登录后原地升级为 Argon2id，不能直接使旧账号失效。
- 限流和用量计数使用 PostgreSQL 原子更新，不引入 Redis。默认限制为：注册/一键试用每 IP 哈希每小时 5 次、登录每 IP 哈希每 15 分钟 20 次、Demo 每天 10 次 LLM 和 100 个 embedding chunks、注册用户每天 30 次 LLM、全站每天 300 次 LLM；所有阈值均可通过环境变量覆盖。
- SQLAlchemy 迁移采用“保持现有 service 接口、替换 store/repository 实现”的方式，不在业务路由中直接写 SQL。迁移目标是数据库结构和访问层，不自动导入 `backend/data/ai_agent.db` 的本地开发数据。
- Neon 应用运行使用池化连接，Alembic 和扩展安装使用直连连接；连接池必须启用 `pool_pre_ping`，数据库错误不得静默回退 SQLite。
- 一键试用在单个事务内写入确定性种子数据，不调用真实模型：包含 1 个目标、3 个任务、1 份已处理资料、闪卡、测试题，以及 1 个等待确认的 Agent Run。重复请求必须创建新的隔离用户，不能共用演示账号。
- 移动端底部固定展示“今日、目标、资料、智能任务、更多”；“更多”中包含问答、复习、进度和账号操作。桌面端继续使用侧边栏。
- 上传文件只保存提取文本和来源元数据，不长期保存原始文件。文件名不得参与服务器路径拼接；PDF 中的文本一律视为不可信资料，不能覆盖系统提示或触发工具。
- 当前真实 embedding 基线固定为 `embedding-3` 和 2048 维；PostgreSQL 使用 `vector(2048)` 与 cosine HNSW 索引。切换模型或维度前必须执行全量重新向量化和对应迁移，启动时发现维度不匹配应立即失败。
- 混合检索分别取关键词和向量 Top 20，使用 RRF `k=60` 融合后返回 Top K；评测必须保留 keyword、dense、hybrid 三组独立结果。

## 实施完成定义

每个 Batch 从前一个已验收提交创建新分支，不能从未验收的并行分支继续堆叠。一个 Batch 只有在代码、自动化测试、浏览器验收、状态文档、需求勾选和独立提交全部完成后才能进入下一 Batch。

每个 Batch 至少执行以下基础门禁；新增的 PostgreSQL、Playwright 和真实模型验收命令在对应 Batch 叠加执行：

```powershell
$env:LLM_PROVIDER="mock"
$env:EMBEDDING_PROVIDER="mock"
$env:LLM_ENV_FILE=".missing-v7-gate.env"
python -m pytest backend/tests -q --tb=short
python -m compileall -q backend
python -m pip check
node --check app/api.js
node --check app/app.js
node --check app/modules/agent-workbench.js
git diff --check
```

若真实指标未达到目标，应记录失败样例和限制，不得通过修改简历措辞掩盖，也不得勾选对应验收项。
