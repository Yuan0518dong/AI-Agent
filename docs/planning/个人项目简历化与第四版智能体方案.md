# 个人项目简历化与第四版智能体方案

更新时间：2026-07-07

> 历史口径修正（2026-07-23）：本文记录第四版启动时的阶段方案。当前对外贡献边界以 `docs/portfolio/个人贡献说明.md` 为准：第一、二版为双人协作，第三版按方向分工，第四版起由维护者独立推进新增能力。不得将本文中的“个人主导”扩展为“整个项目从零独立完成”。

## 1. 项目定位

本项目后续定位为：

```text
AI-Agent：实习期间持续开发、前期协作并在第四版起独立负责的 AI 学习智能体项目
```

对外表达时，应强调这是实习期间唯一持续开发的项目，同时保留前期协作和后期独立负责的边界；它可以作为个人公开作品，但不是公司核心业务或生产系统。

推荐一句话介绍：

```text
一个结合目标管理、资料理解、任务规划、复习反馈和大模型推理的 AI 学习助手，能够根据用户目标、资料、任务完成情况和测试结果，主动判断下一步学习动作，并在用户确认后调整学习路径。
```

## 2. 简历表达边界

可以写：

```text
实习期间持续参与一个面向学习规划场景的 AI Agent 项目：前期与同事协作并负责资料学习和 AI 问答链路，第四版起独立负责后续架构、工程化、评测和发布。
项目覆盖目标管理、资料理解、任务规划、资料问答、闪卡复习、测试反馈和真实模型验收闭环。
```

不要写：

```text
公司核心业务项目
公司内部生产系统
服务公司真实用户
上线公司生产环境
使用公司敏感数据
```

推荐简历结构：

```text
实习经历
- 描述真实实习经历和能力成长。
- 说明 AI-Agent 是实习期间持续投入的项目，以及从协作模块负责人到后期独立负责人的责任变化。

项目经历
AI-Agent：实习项目，前期协作开发、第四版起独立负责人
- 展开项目背景、技术栈、核心功能、Agent 设计和验证结果。
```

这样既能保留“实习期间唯一项目”的事实，也不会把协作基础误写为个人从零完成，或把个人公开作品误写成公司生产业务。

## 3. 当前项目能力基础

当前项目已经具备完整作品集项目的基础：

```text
1. 前端：原生 HTML / CSS / JavaScript 单页应用。
2. 后端：FastAPI + SQLite。
3. 目标链路：目标创建、计划生成、今日任务、打卡、进度统计。
4. 资料链路：资料录入、AI 摘要、chunks、检索、资料问答历史。
5. 复习链路：闪卡、测试题、测试批改、known / review 状态保存。
6. LLM Provider：支持 mock 和 OpenAI-compatible 真实模型。
7. Agent 字段：nextAction、requiresConfirmation、insufficiencyReason、reviewDrafts。
8. 验证：pytest、smoke、node --check、真实模型三类样例验收。
```

当前最适合继续强化的不是单点功能，而是：

```text
把已有目标、资料、任务、复习和测试模块串成完整学习 Agent 闭环。
```

## 4. 第四版目标

第四版定位为：

```text
完整学习智能体闭环 MVP
```

第四版不做通用 Agent 平台，也不追求 AutoGPT 式自动循环。目标是做一个垂直学习场景中的完整 Agent：

```text
观察当前学习状态
-> 判断学习问题
-> 选择下一步动作
-> 调用已有工具生成任务 / 复习草稿 / 补资料建议
-> 用户确认
-> 写入系统
-> 下一轮根据结果继续调整
```

## 5. 第四版核心模块

### 5.1 AgentContext

统一整理 Agent 判断需要的上下文：

```text
目标：当前目标、截止日期、每日学习时间、目标进度
任务：今日任务、逾期任务、完成情况、最近打卡
资料：资料列表、摘要、chunks、关联目标
问答：资料问答历史、资料不足记录、模型回答依据
复习：闪卡状态、复盘草稿、known / review 结果
测试：测试题、答题结果、薄弱点、批改建议
```

交付形态：

```text
backend/app/services/agent_context_service.py
GET /api/agent/context?goalId=...
```

2026-07-07 已完成第一版只读 AgentContext：

```text
1. 支持按 goalId 聚合单目标学习上下文，也支持不传 goalId 的全局上下文。
2. 当前读取目标、任务、进度、资料摘要、chunks 数量、资料问答、资料不足记录、闪卡状态和测试尝试。
3. 返回 summary.observations，供前端工作台展示 Agent 观察到的问题。
4. 第一版只读，不自动重排任务、不自动写入复习草稿或闪卡。
```

当前返回结构重点：

```text
generatedAt
scope: goalId / goalCount / materialCount
summary: 任务、资料、复习、测试、资料不足等聚合观察
goals: 当前目标基础信息
tasks: 今日任务、逾期任务、未完成任务
materials: 摘要、chunks、问答、闪卡、测试状态
qa: 最近问答和资料不足记录
review: 闪卡 new / known / review 状态
quiz: 测试题数量、答题次数和薄弱尝试
progress: 目标进度统计
```

### 5.2 AgentDecision

让模型输出结构化决策，而不是只输出自然语言回答：

```text
stateSummary：当前学习状态摘要
problems：发现的问题
nextAction：下一步动作
reason：为什么建议这样做
requiresConfirmation：是否需要用户确认
proposedActions：建议执行的动作列表
```

推荐动作枚举：

```text
review_material
create_flashcards
create_quiz
reschedule_tasks
create_followup_tasks
ask_for_more_material
answer_only
```

2026-07-07 已完成第一版只读 AgentDecision：

```text
1. 新增 backend/app/services/agent_decision_service.py。
2. 新增 POST /api/agent/decide。
3. 当前使用 rule-based 决策，不依赖真实模型，方便测试和演示稳定。
4. 基于 AgentContext 判断任务滞后、资料未切片、资料未总结、资料不足、测试薄弱点、复习队列和缺少任务等问题。
5. 返回 stateSummary、problems、nextAction、reason、requiresConfirmation、proposedActions。
6. 前端工作台新增“生成建议”，展示问题和待确认动作，但不自动写库。
```

### 5.3 AgentTools

把已有系统能力包装成 Agent 可调用工具：

```text
create_task：生成后续学习任务
reschedule_task：顺延或重排未完成任务
create_review_draft：生成复盘草稿
create_flashcard：在用户确认后写入正式闪卡
suggest_material_gap：提示缺少哪些资料
generate_quiz：基于资料生成测试题
```

第一阶段可以先只做“建议工具调用”，不让 Agent 自动写库；写入动作仍由用户点击确认触发。

### 5.4 AgentActionLog

记录 Agent 的观察、判断、建议和用户反馈：

```text
agent_action_logs
- id
- user_id
- goal_id
- action_type
- observation
- decision
- proposed_payload
- status: proposed / accepted / rejected / applied
- created_at
```

这个模块对简历很重要，因为它证明 Agent 不是一次性问答，而是有持续反馈记录。

2026-07-07 已完成第一版最小 AgentActionLog：

```text
1. 新增 agent_action_logs SQLite 表。
2. 新增 GET /api/agent/action-logs、POST /api/agent/action-logs、PATCH /api/agent/action-logs/{log_id}。
3. 支持 proposed / accepted / rejected / later / applied 状态。
4. 前端工作台 proposedActions 支持采纳、忽略、稍后反馈。
5. 反馈写入后端并在工作台读回展示。
6. 当前只记录反馈，不自动执行 proposedAction。
```

2026-07-07 已补齐 applied 状态闭环：

```text
1. 前端反馈记录支持“标记已执行”。
2. 后端 PATCH /api/agent/action-logs/{log_id} 支持把记录更新为 applied。
3. 当前 applied 只表示用户已处理该建议，不自动触发任务重排或内容写库。
```

2026-07-07 已补齐低风险 proposedAction 执行入口：

```text
1. 执行按钮按 action 类型跳转到资料、记忆、目标或学习页。
2. 跳转后把对应 ActionLog 标记为 applied。
3. 当前仍不自动改任务、不自动写复习草稿、不自动创建闪卡。
```

2026-07-07 已补齐草稿态执行：

```text
1. create_flashcards / create_quiz 执行后进入记忆页，并生成本地复盘草稿。
2. 草稿需要用户点击“加入闪卡”后才写入正式闪卡。
3. ask_for_more_material 执行后预填资料表单，保存前仍可人工修改。
4. 任务类动作仍只跳转目标页，下一阶段再做任务草稿。
5. 设计重点是把 Agent 执行拆成“生成草稿”和“确认写库”两步，降低自动化破坏学习计划的风险。
```

2026-07-07 已补齐任务草稿态执行：

```text
1. create_followup_tasks / reschedule_tasks 执行后生成 agentTaskDrafts。
2. 目标详情页展示任务草稿、建议天数和任务预览。
3. 用户可删除草稿，或按草稿进入现有计划生成确认流程。
4. 当前仍不直接写 tasks 表，避免 Agent 自动覆盖用户学习计划。
```

2026-07-07 已完成上下文回读验收：

```text
1. 用户确认复盘草稿并写入正式闪卡后，前端刷新 AgentContext。
2. 自动化测试验证写入前后 flashcardTotal 发生变化。
3. 自动化测试验证下一轮 AgentDecision 能识别 review_queue。
4. smoke 输出 confirmed write 前后计数和 review_queue 判断结果。
5. 这一点证明 Agent 不是一次性建议，而是能通过系统状态变化进入下一轮判断。
```

### 5.5 Agent 工作台

前端新增一个“智能体工作台”，展示：

```text
1. Agent 看到了什么状态
2. Agent 判断当前最大问题是什么
3. Agent 建议下一步做什么
4. 哪些动作需要用户确认
5. 用户可以采纳、忽略或稍后处理
```

工作台不替代已有页面，而是作为目标、资料、任务和复习之间的总控入口。

2026-07-07 已完成第一版最小展示：

```text
1. 前端新增“智能体”导航和工作台页面。
2. 工作台读取 GET /api/agent/context。
3. 展示观察摘要、任务风险、资料状态、复习队列、测试薄弱点和资料不足记录。
4. 工作台按钮只负责跳转到已有功能页，不自动写库。
5. 后续由 AgentDecision 接入结构化建议和待确认动作。
```

## 6. 第四版验收场景

第四版至少验收 5 个场景：

```text
1. 创建目标并添加资料后，Agent 能给出下一步学习建议。
2. 用户有未完成任务时，Agent 能发现进度滞后并建议重排。
3. 用户测试题答错后，Agent 能生成针对薄弱点的复习草稿。
4. 用户问资料外问题时，Agent 能提示资料不足并建议补资料。
5. 用户采纳建议后，任务 / 草稿 / 闪卡能写入系统并在下一轮上下文中被读取。
```

## 7. 简历项目亮点

简历可提炼为：

```text
1. 独立设计并实现 AI 学习智能体，覆盖目标、资料、任务、复习、测试和进度闭环。
2. 使用 FastAPI + SQLite 构建后端 API 和持久化层，前端使用原生 JavaScript 完成单页交互。
3. 设计 OpenAI-compatible LLM Provider，支持 mock 与真实模型切换，保证测试稳定性和真实模型联调能力。
4. 实现基于资料 chunks 的问答链路，支持资料内回答、引用依据、资料不足判断和历史问答读回。
5. 设计可控 Agent 决策结构，使用 nextAction、requiresConfirmation、insufficiencyReason、reviewDrafts 实现用户确认式写入。
6. 通过 pytest、smoke、真实模型验收样例验证核心链路。
```
