# 个人学习助手后续任务执行文档

更新时间：2026-07-20

## 文档定位

本文档是项目后续开发的唯一任务入口。后续不再按“第几版”组织工作，而是围绕个人学习助手的完整学习闭环，按任务编号实施、验证和勾选。

历史计划、验收报告和真实模型失败证据继续保留，用于追溯项目演进，但不再与本文共同指导当前开发。

## 项目目标

项目继续定位为“基于可控 Agent 的个人学习助手”，核心闭环是：

```text
学习目标
-> 资料摄取与问答
-> 测试发现薄弱点
-> 生成复习内容和后续任务
-> 用户确认
-> 完成学习
-> 根据结果调整下一步
```

借鉴范围：

- Open Notebook / AnythingLLM：目标级学习空间。
- Anki：间隔复习调度。
- RAGFlow：引用来源定位。
- Khoj：每日学习简报。
- Dify：技术执行过程可观察但默认折叠。

不引入多智能体、MCP 市场、播客、联网研究、可视化工作流、电脑控制或前端框架重写。

## 现有功能取舍

### 保留并强化

- 目标、任务、打卡和进度。
- PDF、Markdown、TXT 摄取和混合检索。
- 带引用问答和资料不足拒答。
- 闪卡、测试题和测试记录。
- Agent Runtime、Guard、草稿确认、恢复、幂等和取消。
- PostgreSQL、pgvector、CI、Playwright 和 Mock Demo。

### 整合

- 将目标、资料、学习问答和测试整合到目标级“学习空间”。
- 将“智能助手”改为面向用户的“学习教练”。
- 将闪卡和测试薄弱点统一到“复习”。
- 将 Agent Context、运行状态和观察摘要转化为用户可理解的学习建议。

### 删除或降级

- 主导航不再同时暴露目标、资料和学习等重复入口。
- “智能体验收”、模型模式切换和 Runtime 术语移入折叠的“技术详情”。
- 普通用户不能运行无目标范围的 Agent；执行学习任务前必须选择目标。
- 不删除旧接口和历史运行数据，但新界面不再使用重复入口。
- 不再新建按版本编号组织的需求文档。

最终主导航固定为：

```text
今日 | 学习空间 | 学习教练 | 复习 | 进度
```

目标管理通过学习空间的目标选择器进入；账号操作保留在顶部菜单。

## 执行顺序

必须按以下顺序实施。一个任务完成代码、自动化测试、浏览器验收和文档勾选后，才进入下一个任务。

```text
CORE Agent可靠性
-> SPACE 学习空间
-> REVIEW 间隔复习
-> WEAK 薄弱点闭环
-> COACH 学习教练
-> SOURCE 引用来源详情
-> ACCEPT 完整验收与用户试用
```

## CORE：Agent 底层可靠性

- [ ] `CORE-01` 将模型侧 `create_flashcards/create_quiz` 统一为 `create_review_draft`，使用 `format=flashcard|quiz` 区分内容。
- [ ] `CORE-02` Runtime 根据目标和薄弱点确定 `format`，模型不在含义重叠的动作间盲选。
- [ ] `CORE-03` Guard 继续识别历史动作名称并归一化，旧 AgentStep、ActionLog 和评测数据不迁移、不改写。
- [ ] `CORE-04` 增加脱敏失败分类：`schema_invalid`、`disallowed_action`、`missing_required_field`、`payload_invalid`、`scope_invalid`。
- [ ] `CORE-05` 修正无效草稿评测场景：使用真实存在但不可应用的 draft，经明确确认后触发受控失败；旧场景和结果继续单列保留。
- [ ] `CORE-06` 完成 Mock、Guard、确认恢复、历史动作兼容和固定场景离线回归。
- [ ] `CORE-07` 仅在用户再次明确费用授权后执行固定真实模型评测。

验收要求：

```text
系统工具选择成功率 >= 0.85
确认完整性 >= 0.85
恢复成功率 = 1.0
Guard召回 = 1.0
真实失败Run <= 5
```

达到全部要求前，当前可靠性分支不合并、不部署。

## SPACE：目标级学习空间

- [ ] `SPACE-01` 新增目标级学习空间聚合页；存在目标时必须选择单个目标，不提供全目标 Agent 执行。
- [ ] `SPACE-02` 顶部展示目标名称、科目、截止日期、每日学习时长、完成率和目标管理入口。
- [ ] `SPACE-03` 页面包含“概览、资料、问答、测试”四个区块，复用现有模块和接口，不重写业务服务。
- [ ] `SPACE-04` 概览展示今日任务、资料状态、最近问答、待复习数、薄弱点和待确认草稿。
- [ ] `SPACE-05` 新用户使用三步引导：创建目标、添加资料、开始第一次学习；不向新用户展示全部空页面。
- [ ] `SPACE-06` Demo 用户继续使用确定性种子数据并默认进入“今日”，页面加载不调用真实模型。
- [ ] `SPACE-07` 桌面和移动主导航收敛为“今日、学习空间、学习教练、复习、进度”；旧视图保留为学习空间内部能力。

新增聚合接口：

```text
GET /api/goals/{goal_id}/workspace
```

返回结构：

```text
goal
summary
todayActions
materials
recentQa
dueFlashcards
weakPoints
pendingDrafts
progress
```

`todayActions` 由服务端确定性生成，不因页面加载调用 LLM，并按以下顺序排列：

1. 待确认草稿。
2. 逾期或今日未完成任务。
3. 到期闪卡。
4. 未解决测验薄弱点。
5. 未处理资料或资料不足。
6. 可选巩固学习。

## REVIEW：间隔复习

- [ ] `REVIEW-01` 为 SQLite 和 PostgreSQL 的 `flashcards` 增加 `due_at`、`last_reviewed_at`、`review_count`、`interval_days`、`last_rating`。
- [ ] `REVIEW-02` 旧 `new/review` 闪卡迁移为立即到期；旧 `known` 闪卡迁移为七天后到期。
- [ ] `REVIEW-03` 新闪卡默认立即到期；时间统一使用 UTC ISO 格式存储，前端按本地时区展示。
- [ ] `REVIEW-04` 新增跨资料复习队列，支持按 `goalId` 隔离和只返回当前用户数据。
- [ ] `REVIEW-05` 新增“忘记、困难、良好、简单”四档复习反馈，新界面不再直接修改 `new/known/review`。
- [ ] `REVIEW-06` 保留旧闪卡状态接口用于兼容历史客户端和测试，但不再作为主界面交互。
- [ ] `REVIEW-07` Agent Context 增加到期闪卡数、最近复习结果和按资料聚合的复习队列。

新增接口：

```text
GET /api/review/queue?goalId=...
POST /api/materials/{material_id}/flashcards/{flashcard_id}/reviews
```

提交结构：

```json
{"rating": "again|hard|good|easy"}
```

调度规则：

- `again`：1 天，状态为 `review`。
- `hard`：当前间隔乘以 1.2，最少 1 天，状态为 `review`。
- `good`：首次 1 天、第二次 3 天，之后乘以 2.3，状态为 `known`。
- `easy`：首次 4 天，之后乘以 3.0，状态为 `known`。
- 所有计算结果取整并限制在 1 至 365 天。

## WEAK：测验薄弱点闭环

- [ ] `WEAK-01` 按 `quizId` 聚合答题记录，计算错误次数、最近分数、最近反馈和解决状态。
- [ ] `WEAK-02` 最新一次错误或分数低于 70 的题目视为未解决；最新一次正确且分数不低于 70 时视为已解决。
- [ ] `WEAK-03` 薄弱点展示题目、所属资料、错误次数、最近反馈和建议。
- [ ] `WEAK-04` 提供“重做此题、回到资料、生成复习草稿”三个明确动作。
- [ ] `WEAK-05` Agent Context 增加未解决薄弱点数量、最近错误和已解决变化。
- [ ] `WEAK-06` 用户确认复习草稿后才能生成正式闪卡或针对性测试；模型不得直接写正式数据。

新增接口：

```text
GET /api/review/weak-points?goalId=...
```

默认按错误次数降序、最近错误时间降序排列。

## COACH：学习教练与每日简报

- [ ] `COACH-01` 学习教练默认只展示当前最重要行动、建议原因、预计时长、学习依据和用户操作。
- [ ] `COACH-02` 用户操作统一为“接受、修改、稍后、拒绝”；拒绝结果写入 Feedback Memory，下一次不重复推荐同一动作。
- [ ] `COACH-03` 日常排序和统计由 Runtime 确定性生成；只有生成任务草稿、复习内容或解释复杂问题时才调用模型。
- [ ] `COACH-04` Decision、Guard、Tool、Observation、耗时、Token 和 fallback 移入默认折叠的“技术详情”。
- [ ] `COACH-05` 每日简报直接使用 `workspace.todayActions`，不增加定时任务、通知服务或新的后台队列。
- [ ] `COACH-06` 每周复盘确定性汇总任务完成率、复习数、测验变化和下周建议；模型润色为可选能力且不得改变统计事实。

学习教练默认展示结构：

```text
当前最重要的一项行动
建议原因
预计完成时间
依据：任务、资料、测验或复习状态
接受 | 修改 | 稍后 | 拒绝
```

## SOURCE：引用来源详情

- [ ] `SOURCE-01` 点击问答引用后打开来源详情抽屉。
- [ ] `SOURCE-02` 展示资料名称、PDF 页码或 Markdown 标题、命中片段及前后相邻片段。
- [ ] `SOURCE-03` 使用现有 chunks 接口按 `materialId + chunkIndex` 定位，不新增重复的引用存储。
- [ ] `SOURCE-04` 来源详情提供“在此资料中继续提问”和“生成复习草稿”入口。
- [ ] `SOURCE-05` 明确原始文件不长期保存，不承诺在线打开原 PDF，只展示提取文本和来源位置。

- [ ] `ACCEPT-01` 覆盖闪卡评级、间隔计算、到期队列和旧数据迁移单元测试。
- [ ] `ACCEPT-02` 覆盖 Workspace、复习队列和薄弱点接口的用户隔离与目标隔离测试。
- [ ] `ACCEPT-03` 覆盖 Agent 旧动作兼容、规范动作归一化和 Guard 失败分类测试。
- [ ] `ACCEPT-04` 完成 PostgreSQL/Alembic 与 SQLite 两套迁移验证。
- [ ] `ACCEPT-05` CI 继续使用 Mock Provider，不因页面加载产生真实模型请求。
- [ ] `ACCEPT-06` 保留敏感信息扫描、Ruff、compileall、pgvector、Playwright 和无障碍检查。

Playwright 必须覆盖桌面与 390px 移动端完整流程：

```text
创建目标
-> 上传资料
-> 带引用问答并打开来源详情
-> 完成测试并答错
-> 学习空间出现薄弱点
-> 学习教练生成复习草稿
-> 用户确认
-> 闪卡进入到期队列
-> 用户评级
-> 今日行动和进度更新
```

### 产品验收

- [ ] `ACCEPT-07` 新用户无需理解 Agent 技术术语即可完成首次学习闭环。
- [ ] `ACCEPT-08` 主页面不再出现重复入口和大段 Runtime 技术信息。
- [ ] `ACCEPT-09` 每项建议都能解释推荐原因以及来自哪类学习证据。
- [ ] `ACCEPT-10` 用户答错后能够形成“薄弱点 -> 复习 -> 再测试”的闭环。
- [ ] `ACCEPT-11` 至少邀请 5 名同学自愿试用，其中至少 4 人能在无人工讲解下完成核心流程。
- [ ] `ACCEPT-12` 用户验证只使用现有业务记录和自愿反馈，不增加隐藏行为追踪。

## 执行与维护规则

1. 每次只启动一个最小任务编号，不同时横跨多个模块。
2. 每个任务必须包含代码、测试、用户可见结果和验证证据；只有代码不算完成。
3. 完成后直接在本文勾选，并在对应任务下补充日期、提交和验证结果。
4. 当前事实继续写入 `docs/status/当前状态.md`；实验结果继续写入 `docs/evaluation/`。
5. 真实模型失败样例和旧基线不得删除或改写。
6. 真实模型评测、远程推送、合并和部署仍分别遵守费用与外部操作授权边界。
7. 保持 FastAPI、原生 JavaScript、PostgreSQL/SQLite 和现有部署方案，不因本计划更换技术栈。
