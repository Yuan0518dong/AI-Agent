# 通用成长学习助手 App 第二版项目计划书

更新时间：2026-07-03

> 进度补充：当前第二版已经完成 chunks 前端闭环、agent ask mock 问答闭环、资料历史问答读回、历史问答复盘草稿入口和 OpenAI-compatible Provider 入口。真实 API Key 人工联调和 LangChain 问答链尚未完成。

## 1. 第二版总目标

第二版目标是把第一版“可持久化学习助手 MVP”升级为“具备真实 AI 资料问答能力，并能和目标、计划、记忆、进度主流程联动的学习助手”。

第一版已经完成的基础闭环是：

```text
创建成长目标 -> 添加资料 -> 资料整理 -> 闪卡/测试题 -> 行动计划 -> 今日打卡 -> 进度查看 -> 刷新后数据仍在
```

第二版要在这个闭环上增加真实 AI 能力，让项目不再只是“页面和数据能跑”，而是能展示一个更完整的学习助手场景：

```text
用户围绕目标添加资料 -> 基于资料向 AI 提问 -> 获得可信回答和学习建议 -> 建议能辅助计划和复习 -> 问答和学习过程可保存、可复盘、可验收
```

第二版完成后，项目应该能够作为“真实 AI 工程实践版本”进行展示。

## 2. 第二版要解决的用户问题

第一版解决的是“学习流程能不能跑通、数据能不能持久化”。

第二版要解决的是“用户真正学习时，AI 能不能帮助理解资料并推进学习”。

核心用户问题：

```text
1. 用户添加资料后，仍然不知道某些概念怎么理解。
2. 用户希望围绕资料追问，而不是只获得一次性摘要。
3. 用户希望 AI 回答基于自己的资料，而不是泛泛聊天。
4. 用户希望资料不足时，AI 能说明边界，而不是编造。
5. 用户希望 AI 给出下一步学习建议，帮助计划和复习。
6. 用户希望学习问答记录能保存，后续可以复盘。
7. 团队希望第二版能体现真实 AI 工程能力，而不是继续停留在 mock AI。
```

第二版核心用户故事：

```text
作为一个学习者，
我希望围绕自己的成长目标和已添加资料向 AI 提问，
系统能够基于资料给出可信回答，
当资料不足时说明边界，
同时给出标注清楚的通用学习建议，
并把问答过程保存下来，方便后续复盘和继续学习。
```

## 3. 第二版范围总览

第二版沿用第一版的两条业务链路，不重新按“前端 / 后端”切分。

第一版协作链路：

```text
陈：目标管理 -> 行动计划 -> 今日任务 -> 打卡 -> 进度统计
赵：资料管理 -> AI 整理 -> 闪卡 / 测试题 -> 成长问答
```

第二版在第一版基础上继续演进：

```text
陈：目标推进链路 + AI 检索 / 问答后端底座
赵：资料学习链路 + AI 能力在资料学习流程里的落地
共同：问答 API、返回结构、目标上下文、资料不足规则和整体验收
```

第二版包含四条主线：

```text
1. 资料学习主线：资料录入、整理、闪卡、测试题、chunks 前端接入和问答入口。
2. 目标推进主线：目标、计划、任务、打卡、进度，以及 AI 建议和目标上下文联动。
3. AI 问答底座主线：chunks、关键词检索、上下文拼接、真实大模型 / LangChain 问答链。
4. 工程验收主线：测试、smoke、README、验收文档、dev 集成和 main 稳定发布。
```

第二版不是重做第一版，也不是直接做完整 Agent / RAG。

第二版的合理定位是：

```text
在第一版持久化学习闭环上，补上真实 AI 资料理解与问答能力，并保证它能进入项目主流程。
```

当前 `dev` 已经合入的第二版基础能力：

```text
1. material_chunks 数据表。
2. POST /api/materials/{material_id}/chunks。
3. GET /api/materials/{material_id}/chunks。
4. GET /api/materials/search?query=...&limit=...
5. RAG chunks 接口说明文档。
6. POST /api/agent/ask mock 问答接口。
7. GET /api/materials/{material_id}/qa 历史问答读回接口。
8. material_qa_records 问答记录持久化。
9. LLM Provider 抽象和 MockLLMProvider fallback。
```

因此第二版后续不是从零开始做 RAG，而是在已有 chunks / 关键词检索基础上继续完成前端学习入口、问答接口和整体验收。

截至 2026-07-03，赵负责的资料学习链路已完成：

```text
1. 资料总结区 chunks 生成、读回和搜索展示。
2. 成长问答页接入 POST /api/agent/ask。

7. 资料链路浏览器 smoke 验证。
```

截至 2026-07-03，陈负责的 AI 问答后端底座已完成：

```text
1. chunks 检索和 goal/material 过滤。
2. POST /api/agent/ask 统一问答返回结构。
3. material_qa_records 问答记录保存和按资料读回。
4. LLM Provider 抽象，默认 MockLLMProvider。

```

当前第二版剩余公共判断：

```text
1. 是否把 mock Provider + OpenAI-compatible Provider 入口作为第二版阶段验收版本。
2. 是否本轮继续使用真实 API Key 做人工联调。

4. 是否需要按目标筛选问答历史。
```

## 4. LangChain 是否进入第二版

建议进入第二版。

但 LangChain 的角色必须明确：

```text
LangChain 是第二版 AI 问答链的工程实现方式，不是第二版的产品目标本身。
```

第二版使用 LangChain 的目的：

```text
1. 训练真实 AI 工程能力。
2. 管理资料上下文注入。
3. 管理 Prompt 模板。
4. 约束结构化输出。
5. 为后续 RAG / Agent 留出 AI service 边界。
```

第二版不使用 LangChain 做：

```text
1. LangChain memory。
2. 完整 Agent 循环。
3. 多工具自动调用。
4. 向量数据库检索。
5. 完整 RAG。
```

## 5. 第二版最小产品闭环

第二版必须跑通的最小闭环是：

```text
选择成长目标
-> 添加或选择一份资料
-> 围绕资料向 AI 提问
-> AI 基于资料回答
-> AI 给出学习建议
-> 保存问答记录
-> 用户刷新后仍可查看
-> 用户可以基于回答继续复习或推进任务
```

当前完成度：

```text
已完成到“用户可以基于回答继续复习”的前端草稿入口。
尚未完成“AI 建议自动辅助计划或任务草稿”，第二版当前仍坚持不自动修改目标和计划。
```

这个闭环要服务整个产品，而不是只服务资料模块。

它和第一版模块的关系：

```text
目标模块：提供当前学习目标和用户意图。
资料模块：提供 AI 回答依据。
问答模块：提供真实 AI 交互能力。
记忆模块：后续可以基于问答结果生成或补充复习内容。
计划模块：后续可以基于 AI 建议生成待确认任务。
进度模块：后续可以统计问答、复习和任务推进情况。
```

## 6. 第二版必做功能

### 6.0 已有基础能力

当前 `dev` 已具备 RAG chunks 基础链路：

```text
1. 资料 content 可以切分为 material_chunks。
2. chunks 可以保存到 SQLite。
3. 可以按资料读取 chunks。
4. 可以用关键词搜索 chunks。
5. 后端测试和 smoke 已覆盖基础链路。
```

这部分作为第二版基础，不再重复规划为待做功能。后续任务是在此基础上接入资料学习流程和 AI 问答流程。

### 6.1 AI 资料问答

```text
1. 用户可以围绕已有资料进行提问。
2. 问答后端可以复用 chunks / 搜索结果作为上下文。
3. 后端真实调用大模型，必要时使用 LangChain 管理 Prompt 和输出结构。
4. 回答包含答案、依据、建议、来源资料和可信度。
5. 资料不足时，AI 必须说明资料不足。
6. 资料不足时，可以给通用建议，但必须标注不是来自当前资料。
7. 问答记录保存到 SQLite。
8. 刷新后可以读取历史问答。
```

### 6.2 目标上下文接入

```text
1. 问答请求可以带 goalId。
2. AI 回答时可以知道当前目标名称、方向、当前水平和重点难点。
3. 回答建议要尽量贴合当前目标。
4. 不自动修改目标和计划，只给建议。
```

### 6.3 前端体验接入

```text
1. 在资料页或资料详情中提供 chunks 生成、读回和搜索入口。
2. 在资料页或资料详情中提供“问 AI”入口。
3. 问答区域可以展示历史记录。
4. 回答展示要区分答案、依据、建议和来源。
5. 资料不足时要有明确提示。
6. 保持第一版目标、资料、计划、打卡、进度主流程可用。
```

### 6.4 记忆和复习联动准备

第二版不强制自动生成复杂复习计划，但要保留联动入口：

```text
1. 问答结果中可以出现“建议复习点”。
2. 后续可以从问答结果生成闪卡或测试题。
3. 第二版先不自动写入闪卡和任务，避免范围失控。
```

当前进度：

```text
已完成从问答结果生成前端复盘草稿，包括闪卡草稿和复习点。
当前不自动写入后端 flashcards / quiz_questions，也不自动写入任务。
```

### 6.5 工程化验收

```text
1. 新增或更新后端测试。
2. 更新 smoke 脚本或新增 v2 smoke。
3. 更新 README 中的大模型配置说明。
4. 新增第二版验收记录。

```

## 7. 第二版可选增强

如果必做功能提前稳定，可以选择做以下增强：

```text
1. 简易多资料检索：基于标题、摘要、关键词匹配，不上向量数据库。
2. 从 AI 回答中生成“建议任务”，但必须用户确认后才写入任务列表。
3. 从 AI 回答中生成“建议复习点”，但必须用户确认后才写入记忆模块。
4. 增加问答质量反馈：有帮助 / 没帮助。
5. 增加问答记录按目标或资料筛选。
```

这些增强不作为第二版必过标准。

## 9. 分支策略

按照当前团队协作方式推进。第二版不强制新建新分支，优先沿用当前已经存在、双方熟悉的个人功能分支：

```text
每个人一个功能分支 -> 合并到 dev 集成测试 -> dev 稳定后再合并 main
```

```text

陈负责分支：继续沿用陈当前负责目标/计划主流程的个人功能分支
集成分支：dev
稳定分支：main
```

分支规则：

```text
1. 个人功能分支先同步最新 origin/dev。
2. 各自在自己的 feature 分支开发，不直接改 main。
3. 涉及接口字段和数据表前，先在文档中确认。
4. 每个 feature 分支完成后，先本地跑测试。
5. 测试通过后合并到 dev。

8. main 只保留稳定、可演示、验收通过的版本。
9. 只有当原个人分支已经合并、废弃或承担完全不同任务时，才新建第二版专项分支。
```

## 12. 数据表草案

建议新增 `material_qa_records` 表：

```text
id
material_id
goal_id
question
answer
basis
suggestion
source_title
is_from_material
confidence
created_at
```

字段说明：

```text
material_id：保证问答和资料稳定关联。
goal_id：让问答能接入目标上下文。
question：保存用户原始问题。
answer：保存 AI 回答。
basis：保存回答依据，避免只有结论。
suggestion：保存学习建议，体现学习助手价值。
source_title：方便前端展示来源。
is_from_material：区分是否主要来自资料。
confidence：给验收和 UI 提示留下基础判断。
created_at：支持历史记录和复盘。
```

## 13. AI 回答规则

回答必须遵守：

```text
1. 优先基于当前资料回答。
2. 如果带入 goalId，则结合目标上下文给建议。
3. 不确定时不能编造。
4. 资料不足时必须明确说明。
5. 通用建议可以给，但必须标注不是来自当前资料。
6. 回答要尽量清楚、简洁、适合学习者理解。
```

资料不足时推荐格式：

```text
当前资料不足以直接回答这个问题。

基于通用学习经验，可以参考以下建议：
...

注意：以上建议不是来自当前资料，需要你补充相关资料后再确认。
```

## 14. 验收标准

### 14.1 用户流程验收

```text
1. 可以创建或选择一个成长目标。
2. 可以添加或选择一份资料。
3. 可以在资料页或资料详情中向 AI 提问。
4. AI 返回答案、依据、建议和来源资料。
5. 问答记录可以保存。
6. 刷新页面后问答记录仍然存在。
7. 第一版目标、资料、计划、打卡、进度主流程仍然可用。
```

### 14.2 AI 可信度验收

至少准备三类测试问题：

```text
1. 资料中有明确答案：AI 应准确回答，并给出依据。
2. 资料中只有部分答案：AI 应说明只能回答一部分。
3. 资料中没有答案：AI 必须说明资料不足，不能编造。
```

资料不足时必须满足：

```text
1. 明确说当前资料不足。
2. 可以给通用建议。
3. 明确标注通用建议不是来自当前资料。
```

```text
1. python -m pytest backend/tests -v 通过。
2. python backend/smoke_api.py 通过，或新增 v2 smoke 通过。
3. dev 分支浏览器主流程通过。
4. README 包含大模型配置说明。
5. docs/status 中新增第二版验收记录。
6. CI 不因第二版改动失败。
```

### 14.4 协作验收

```text
1. 赵的分支能独立说明资料学习链路：资料整理、chunks 接入、问答入口和学习展示。

```

## 17. 风险和降级方案

### 17.1 大模型调用不稳定

降级方案：

```text
保留 mock AI fallback，但页面和文档必须明确当前使用的是 fallback。
```

### 17.2 LangChain 接入耗时超预期

降级方案：

```text
先抽象 AI service 接口，内部直接调用大模型 API。
LangChain 放到下一步替换，但接口和 Prompt 结构保持一致。
```

### 17.3 多资料检索范围失控

降级方案：

```text
第二版只做单资料问答。
多资料检索写入第三版规划。
```

### 17.4 AI 回答容易编造

降级方案：

```text
收紧 Prompt。
增加资料不足测试样例。
回答结构中强制返回 isFromMaterial 和 confidence。
```

### 17.5 合并影响第一版主流程

降级方案：

```text
所有功能先进 feature 分支。
合并 dev 后必须复跑第一版主流程。
main 只接收验收稳定版本。
```
