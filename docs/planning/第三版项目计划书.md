## 2. 第三版为什么这样收束

第二版已经能演示的主流程：

```text
创建目标
-> 添加资料
-> 生成资料摘要和练习
-> 生成 chunks 并检索
-> 基于资料提问
-> 展示 answer / basis / suggestion / references / confidence
-> 保存并读回历史问答
-> 从历史问答生成复盘草稿
-> 用户确认加入正式闪卡
-> 闪卡 known / review 状态保存
-> 今日任务打卡和进度统计仍可用
```

第三版要补的不是“能不能演示”，而是：

```text
1. 让 AI 回答升级为可控学习智能体输出。
2. 让系统能判断资料是否足够，而不是只要模型能答就算成功。
3. 让每次建议都有 nextAction、依据、置信度和用户确认边界。
4. 让最终项目有清楚的验收记录、演示脚本和交接说明。
```

第三版不追求完整自动 Agent 循环。这里的“智能体”定义为：

```text
上下文感知：读取目标、资料、chunks、问答历史和复习状态。
有限决策：判断回答、复习、生成草稿、补资料或只展示答案。
可追踪输出：保留 answer、basis、references、confidence、nextAction。
确认写入：任何正式闪卡、测试题或任务都必须由用户确认后写入。
```

## 3. 第三版最终目标

第三版最终目标分为三层。

### 3.1 稳定交付

```text

2. 保持默认测试和 smoke 不依赖真实 API Key。

4. 明确 dev / main 的最终交付状态。
```

### 3.2 智能体最小实现

在现有 `POST /api/agent/ask` 链路上，补充最小智能体决策输出：

```text
nextAction
requiresConfirmation
insufficiencyReason
reviewDrafts
```

目标是让一次资料问答不只返回回答，还能给出下一步学习动作。

建议最小输出结构：

```json
{
  "answer": "...",
  "basis": "...",
  "suggestion": "...",
  "references": [],
  "isFromMaterial": true,
  "confidence": "medium",
  "mode": "mock",
  "nextAction": "create_flashcards",
  "requiresConfirmation": true,
  "insufficiencyReason": "",
  "reviewDrafts": [
    {
      "type": "flashcard",
      "front": "...",
      "back": "...",
      "source": "agent_qa"
    }
  ]
}
```

最小 `nextAction` 枚举：

```text
answer_only：资料能回答，但暂不需要生成复习内容。
review_material：资料部分相关，建议回看资料或补充复习点。
create_flashcards：资料能明确回答，适合生成闪卡草稿。
create_quiz：资料能明确回答，适合生成测试题草稿。
ask_for_more_material：资料不足，不能把常识回答伪装成资料结论。
```

## 9. 三类 AI 评估样例

第三版至少保留三类样例，作为“智能体可信度”的验收依据。

### 9.1 资料有答案

```text
资料包含：RAG 会先检索相关资料片段，再基于片段生成回答，减少凭空编造。
问题：RAG 为什么能减少模型编造？
期望：
- isFromMaterial=true
- confidence=high 或 medium
- references 至少 1 条
- nextAction=create_flashcards 或 create_quiz
- requiresConfirmation=true
- insufficiencyReason 为空
```

### 9.2 资料部分有答案

```text
资料包含：RAG 使用检索片段辅助回答。
问题：RAG 和 LangChain memory 有什么区别？
期望：
- confidence=medium 或 low
- answer 必须说明资料只覆盖 RAG，没有覆盖 LangChain memory
- nextAction=review_material 或 ask_for_more_material
- insufficiencyReason 说明缺少 LangChain memory 信息
```

### 9.3 资料无答案

```text
资料包含：如何把历史问答转换成闪卡，并保存 known / review 状态。
问题：Transformer 的多头注意力公式是什么？
期望：
- isFromMaterial=false
- confidence=low
- nextAction=ask_for_more_material
- requiresConfirmation=false
- reviewDrafts=[]
- insufficiencyReason 说明资料未提及 Transformer、多头注意力或公式
```

## 11. 最终演示脚本

建议最终演示只走一条稳主线：

```text
1. 创建或选择一个成长目标。
2. 添加一份学习资料。
3. 生成资料 chunks。
4. 围绕资料提问。
5. 展示 AI 回答、依据、来源片段、confidence。
6. 展示 Agent nextAction、requiresConfirmation、insufficiencyReason。
7. 从历史问答生成复盘草稿。
8. 用户确认加入正式闪卡。
9. 在记忆页点击“已掌握 / 还要复习”，刷新后状态仍在。
10. 回到今日任务完成一次打卡，查看进度仍正常。
11. 用一个资料不足问题验证 Agent 不编造。
```

## 12. 最终项目表达

对外表达建议：

```text
这是一个通用成长学习助手，从目标管理、资料学习、行动计划到复习记忆形成完整闭环。

第一版完成了目标、资料、计划、任务、打卡、进度和记忆内容的 SQLite 持久化。

第二版完成了 AI 资料问答闭环：资料 chunks、关键词检索、基于资料回答、历史问答保存、复盘草稿和正式闪卡复习。

第三版完成了可控学习智能体 MVP：系统能够基于目标和资料上下文判断资料是否足够，输出下一步学习动作，生成待确认复习草稿，并通过三类样例验证 AI 不编造。
```

面试表达重点：

```text
1. 我不是只做页面，而是按业务链路负责资料学习闭环。
2. 我把 AI 输出设计成结构化结果，而不是不可复用的一段文本。
3. 我用资料不足规则和三类评估样例约束模型不编造。
4. 我坚持用户确认后写入，避免 AI 自动污染正式学习数据。
5. 我用 pytest、smoke、浏览器主流程和文档完成工程验收。
```
