# 语义检索升级计划

更新时间：2026-07-09

## 目标

把当前资料 chunks 的关键词 / 字符串匹配检索，升级为 embedding 向量相似度检索。

目标不是一次性引入完整向量数据库，而是在现有 SQLite + FastAPI 架构里完成一个可测试、可回退、可讲清楚的 RAG 检索层升级。

## 第一阶段实施状态

```text
状态：已完成（2026-07-15）。
已新增 EmbeddingProvider / MockEmbeddingProvider，并在 SQLite material_chunks 中用 JSON TEXT 保存向量。
检索已升级为 cosine similarity Top-K 语义优先、关键词补位和异常 fallback。
Agent references 已透传 searchMode 和浮点 score，置信度判断已适配两种分数量纲。
验证：backend/tests 55 passed；默认 Mock smoke 通过；compileall 和 git diff --check 通过。
```

## 当前问题

```text
backend/app/services/material_ai_service.py 里的 chunk 检索仍以关键词 / 字符串匹配为主。
当用户换一种说法提问时，系统可能找不到语义相关的 chunk。
这会影响资料问答、资料不足判断和后续 AgentDecision 的输入质量。
```

## 第一阶段范围

```text
1. 保留现有关键词检索作为 fallback。
2. 新增 EmbeddingProvider 抽象，测试环境使用 MockEmbeddingProvider。
3. 为 material_chunks 增加 embedding 存储能力。
4. 生成 / 更新 chunks 时同步生成 embedding。
5. 查询时对 question 生成 query embedding，计算 cosine similarity，返回 Top-K chunks。
6. 后端测试覆盖：语义相近但关键词不完全一致的查询能命中目标 chunk。
```

## 暂不做

```text
1. 不引入独立向量数据库。
2. 不做完整 LangChain RAG 重构。
3. 不依赖外网 embedding API 通过 CI。
4. 不改 Agent 自动执行边界。
5. 不大改前端信息架构。
```

## 推荐实现路线

```text
1. 先读 backend/app/services/material_ai_service.py 和 material_store.py。
2. 找到 chunks 创建、读取、搜索的现有路径。
3. 新增 embedding provider：
   - mock：用确定性小向量，保证测试稳定。
   - optional real：后续再接 sentence-transformers 或 OpenAI-compatible embedding。
4. SQLite 存储建议先用 JSON TEXT 保存向量，降低迁移复杂度。
5. 搜索排序：
   - 有 embedding 时按 cosine similarity 排序。
   - embedding 缺失或 provider 不可用时回退关键词检索。
6. 更新 docs/api/RAG-chunks接口说明.md，说明检索策略从关键词升级为语义优先、关键词兜底。
```

## 验收标准

```text
1. 旧关键词搜索接口仍可用。
2. 新测试证明语义近义查询能命中目标 chunk。
3. 缺失 embedding 或 provider 失败时不影响原有问答流程。
4. python -m pytest backend/tests -v 通过。
5. python backend/smoke_api.py 通过。
6. README 或 RAG 文档能讲清：从“会调接口”升级到“理解 RAG 检索层”。
```

## 面试表达

```text
我没有一上来引入向量数据库，而是在现有 SQLite chunks 表上先加 embedding 和 cosine similarity 检索。
这样可以用最小成本验证语义召回效果，并保留关键词检索作为 fallback。
这个升级重点是把 RAG 的检索层从字符串匹配推进到语义相似度，而不是单纯调用大模型接口。
```
