# 第一版功能开发边界与分工

## 1. 第一版目标

第一版的目标是做出一个可以完整演示的最小可用版本。

核心不是把所有想法都做进去，而是先跑通一条完整闭环：

```text
注册登录 -> 创建成长目标 -> 添加资料 -> AI 整理资料 -> 生成行动计划 -> 完成今日打卡 -> 查看进度
```

只要用户能够顺利完成这条流程，第一版就算达标。

## 2. 第一版产品边界

第一版定位为“通用成长学习助手 App”的基础版本。

它面向学生、上班族、宝妈/宝爸、考证人群、自由职业者和兴趣学习者等多类人群，帮助用户围绕一个成长目标进行资料整理、计划拆解、记忆练习和进度监督。

第一版重点验证：

1. 用户是否愿意创建自己的成长目标。
2. 用户是否愿意添加资料给 AI 整理。
3. AI 整理出的摘要、知识点、计划是否有帮助。
4. 每日任务和打卡是否能推动用户继续使用。
5. 进度展示是否能给用户反馈感。

## 3. 第一版必须实现的功能

### 3.1 用户基础

必须实现：

- 简单注册
- 简单登录
- 退出登录
- 用户数据隔离

验收标准：

- 用户可以注册账号并登录。
- 登录后只能看到自己的目标、资料、计划和进度。
- 刷新页面后登录状态和数据不应异常丢失。

### 3.2 成长目标管理

必须实现：

- 创建目标
- 查看目标列表
- 查看目标详情
- 修改目标
- 删除目标

目标字段：

- 目标名称
- 所属方向：学习、考试、职场、育儿、兴趣、健康等
- 当前水平
- 目标完成时间
- 每天可投入时间
- 重点难点说明

验收标准：

- 用户可以完整创建一个目标。
- 创建成功后目标出现在列表中。
- 用户可以修改目标信息。
- 删除目标前必须二次确认。
- 删除目标后，与该目标相关的计划和进度也要正确处理。

### 3.3 资料管理

必须实现：

- 添加文本资料
- 添加网页链接
- 查看资料列表
- 查看资料详情
- 删除资料

建议第一版后半段再做：

- PDF 上传与解析

验收标准：

- 用户可以添加一段文本资料。
- 用户可以添加一个网页链接。
- 资料可以关联到某个成长目标。
- 资料保存后可以再次查看。
- 删除资料前必须二次确认。

### 3.4 AI 整理资料

必须实现：

- 根据资料生成摘要
- 提炼知识点
- 给出学习或行动顺序
- 支持围绕资料提问

AI 输出至少包括：

- 资料摘要
- 关键知识点
- 难点解释
- 建议学习顺序
- 可执行的小任务

验收标准：

- 用户添加资料后，可以触发 AI 整理。
- AI 整理结果能保存下来。
- 用户刷新页面后仍能查看整理结果。
- 用户可以基于资料进行追问。

### 3.5 行动计划

必须实现：

- 根据目标和截止时间生成每日计划
- 今日任务展示
- 任务完成打卡
- 查看计划列表
- 简单延期调整

验收标准：

- 用户创建目标后，可以生成行动计划。
- 今日页面能看到当天任务。
- 用户可以勾选任务完成。
- 完成状态刷新后仍然保留。
- 如果任务延期，系统可以给出简单调整建议。

### 3.6 记忆与练习

必须实现：

- 根据资料生成闪卡
- 根据资料生成简单测试题
- 标记“已掌握”
- 标记“需复习”

验收标准：

- 用户可以看到由资料生成的闪卡。
- 用户可以查看简单测试题和参考答案。
- 用户可以标记某张闪卡是否掌握。
- “需复习”的内容后续可以在复习列表中看到。

### 3.7 进度统计

必须实现：

- 目标完成率
- 今日任务完成情况
- 已完成任务数
- 资料数量
- 闪卡数量
- 简单进度条

验收标准：

- 用户可以看到每个目标的完成进度。
- 完成任务后，进度会同步变化。
- 进度页面能反映用户当前执行情况。

## 4. 第一版明确不做的功能

以下内容不进入第一版开发范围：

- 老师端
- 家长端
- 企业管理端
- 社区、评论、好友系统
- 支付系统
- 多人协作学习
- 复杂课程体系
- 语音对话
- 视频生成
- 完整推荐算法
- 复杂多智能体架构
- 移动端正式上架
- 学校或企业内部系统接入

这些功能可以先记录到后续迭代，不要影响第一版主流程。

## 5. 两人模块分工

### 5.1 你负责：产品、体验、验收

主要负责：

- 维护 PRD
- 决定第一版功能边界
- 设计页面流程
- 写清楚每个功能怎么用
- 测试同事开发出来的功能
- 收集反馈
- 判断功能是否可以验收
- 管理任务优先级
- 记录需求变更

你重点关注：

- 这个功能是不是第一版必须做？
- 用户能不能看懂？
- 页面流程是否顺畅？
- 功能做完后是否真的解决问题？
- 哪些需求应该放到后续版本？

### 5.2 同事负责：技术、开发、部署

主要负责：

- 搭建前端项目
- 搭建后端项目
- 设计数据库
- 实现登录、目标、资料、计划、打卡等功能
- 接入 AI 接口
- 处理 Git 分支和代码合并
- 部署测试环境
- 修复 bug
- 保证基础代码质量

同事重点关注：

- 功能是否稳定可用？
- 数据是否正确保存？
- 用户数据是否隔离？
- AI 接口失败时如何处理？
- 后续功能是否方便扩展？

## 7. 第一版开发优先级

建议按以下顺序开发：

1. 项目基础结构
2. 登录注册
3. 成长目标管理
4. 资料管理
5. AI 资料整理
6. 行动计划生成
7. 今日任务与打卡
8. 闪卡和测试题
9. 进度统计
10. 整体联调和演示版本

## 8. 第一版总体验收标准

第一版最终验收时，必须能够完成以下流程：

1. 用户注册并登录。
2. 用户创建一个成长目标。
3. 用户添加一份资料。
4. 系统通过 AI 整理资料重点。
5. 系统根据目标生成行动计划。
6. 用户在今日页面完成任务打卡。
7. 用户查看目标进度。
8. 用户可以看到由资料生成的闪卡或测试题。

如果以上流程可以稳定完成，就说明第一版已经达到开发边界，可以进入下一阶段优化。

## 9. 当前提醒

第一版最怕功能发散。

开发过程中如果出现新想法，先记录到“后续迭代”，不要立即加入当前版本。当前阶段只围绕一条主线推进：

```text
目标 -> 资料 -> AI 整理 -> 计划 -> 打卡 -> 进度
```
