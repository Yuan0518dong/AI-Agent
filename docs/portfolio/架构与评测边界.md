# 架构与评测边界

## 运行架构

```text
同源浏览器
  -> FastAPI 路由
  -> 会话、限流、Origin 校验
  -> 资料上传/解析 -> chunk + embedding -> keyword/dense/RRF
  -> 问答引用或 grounded-refusal
  -> Agent Runtime -> Tool Registry -> Decision Guard -> 确认/恢复/取消
  -> SQLite（本地与测试）或 Neon PostgreSQL + pgvector（生产）
```

PDF、Markdown 和 TXT 的原文件只在请求内存中解析；持久化的是提取文本与来源定位，不是原文件。资料文本按不可信输入处理，不能覆盖系统规则或触发工具。

## Batch 4 口径

- 检索：对固定 10 份资料与 50 条中文查询分别运行 keyword、dense、hybrid，报告 Recall@3、Recall@5、MRR、nDCG@5、p50/p95 延迟。
- 问答：固定 32 条，分别覆盖可回答、跨资料、资料不足和冲突资料；引用准确率要求所有返回引用均属于标注资料，groundedness 要求材料回答包含可接受引用。
- Agent：固定 20 场景保留 Mock 回归；Mock Token/成本为零，不能用于真实 Provider 成功率、Token 或成本结论。
- 真实模型：必须通过已配置的 DeepSeek Provider，20 个 Agent 场景各运行 3 次；创建 Run 的初始快照不调用模型，执行阶段使用 `llm-json`。每个真实请求发送前限制为 12,000 UTF-8 字节和 350 completion token，格式修复重试关闭；请求和成本预算在 Provider 边界预留并强制执行。输出不得含 API Key、Authorization、Cookie、连接串、密码或用户隐私数据。

## 真实 Agent 结果

受授权的固定运行已完成 20 场景 x 3，即 60 个 Run；产生 107 次 Provider 请求，prompt/completion Token 为 `237971/33611`，按公开 cache-miss 费率估算成本 `$0.042727`。工具选择成功率 `0.6333`、确认完整性 `0.5556`、恢复成功率 `1.0`，p50/p95 延迟 `5781/9750 ms`。22 个 Run 未满足场景断言，安全回退累计 84 次，均保留在 [真实模型报告](../evaluation/第七版Batch4Agent真实模型评测报告.json)。

Guard 召回 `1.0` 的口径是：真实 Provider 返回一次决策后，固定注入非法 JSON，验证 Guard 是否拦截。因此它只能证明 Guard 链路，不能解释模型的自然非法输出率；也不能以 Mock Agent 的 `1.0` 覆盖真实工具选择和确认指标。

## 当前限制

资料不足评测初始 F1 为 0.4，失败集中在 `qa18` 至 `qa23`。查询侧中文二字 n-gram 将问句模板与无关资料相交；修复为查询侧三至四字 n-gram 与停用词过滤后，固定集 F1 为 0.8571。初始失败、修复方法和相同固定样例保留在 `docs/evaluation/第七版Batch4资料不足修复记录.md`。

冲突资料样例仅验证返回引用是否位于两份条件不同的资料中；系统尚未实现冲突检测、来源权重或自动裁决。

真实 Agent 工具选择和确认完整性均未达到可作为稳定能力宣传的水平；后续修改提示词、工具描述或夹具后必须重新执行完整 20 x 3 固定评测，不能删除当前失败数据。
